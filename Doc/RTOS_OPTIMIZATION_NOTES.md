# RTOS 后续优化笔记

这份笔记用于记录：在完成最基础的 RTOS 学习之后，可以继续优化和扩展的方向。

当前阶段不要急着做这些优化。先把任务创建、首次任务启动、PendSV 上下文切换、SysTick、任务延时、临界区这些基本机制学通。等基本 RTOS 能跑起来之后，再回来逐项看这份清单。

## 1. 内存管理优化

### 当前 first-fit 堆分配器

当前学习工程里的堆分配器使用的是空闲链表加 first-fit 算法：

```text
head -> 空闲块 -> 空闲块 -> tail
```

分配时，从链表头开始找第一块足够大的空闲块。如果这块内存比申请大小大很多，就切分出一块新空闲块，重新挂回链表。

释放时，把释放块按地址顺序插回空闲链表，并尝试和前后相邻的空闲块合并。

后续可以优化的点：

- `free` 时检查传入指针是否为 `NULL`。
- 检查释放地址是否在堆范围内。
- 尽可能检测重复释放。
- `malloc` 和 `free` 加临界区保护，避免多任务同时修改空闲链表。
- 记录最小剩余堆空间。
- 记录分配失败次数。

### 碎片问题

first-fit 会产生外部碎片：

```text
空闲总量足够，但没有单个连续空闲块足够大。
```

可以研究的改进方向：

- best-fit：找最接近申请大小的空闲块，可能减少剩余碎片，但搜索成本更高。
- next-fit：从上次搜索结束的位置继续找，减少每次都从头开始扫描。
- 地址有序空闲链表：方便释放时合并相邻块，当前实现已经使用了这个思路。
- 分离空闲链表：不同大小范围维护不同链表，减少搜索时间。

### 位图固定块分配器

位图分配器把一整块堆切成固定大小的小块，然后用 bitmap 记录每块是否被使用：

```text
block 0 | block 1 | block 2 | block 3 | ...
bitmap: 0          1          0          0
```

优点：

- 元数据简单。
- 释放操作快。
- 行为更可预测。
- 适合 RTOS 中大小比较固定的对象。

缺点：

- 块太小：内部碎片少，但 bitmap 变大，搜索成本增加。
- 块太大：搜索简单，但小对象会浪费更多内存。
- 没有 MMU 的 MCU 上，大块申请仍然需要连续物理块。

可以单独做一个实验：

```c
void *block_alloc(size_t size);
void block_free(void *ptr);
```

先做单一固定块大小，再和当前 first-fit 堆分配器做对比。

### 多级内存池

更实用的小型 RTOS 设计通常会使用多个固定大小的内存池：

```text
16 字节池
32 字节池
64 字节池
128 字节池
256 字节池
```

申请内存时，选择能容纳请求大小的最小池。

例如：

```text
申请 20 字节 -> 使用 32 字节池
申请 70 字节 -> 使用 128 字节池
```

这样比单一固定块大小更节省内存，也比通用 heap 更可预测。

适合放进内存池的对象：

- TCB。
- 信号量对象。
- 队列控制块。
- 消息节点。
- 小型 buffer。

### 混合分配器

后续可以设计成：

```text
小型 RTOS 对象 -> 固定大小内存池
大 buffer       -> 通用 heap
```

这样既能保证常用 RTOS 对象分配快速稳定，又保留大块动态内存的灵活性。

## 2. 调度器优化

### 优先级位图

当前工程使用位图查找最高优先级 ready 任务，这是 RTOS 中很常见的技巧。

后续可以思考：

- 如果两个任务优先级相同怎么办？
- 是否需要同优先级时间片轮转？
- idle task 是否必须永远处于 ready 状态？
- 如果没有任何 ready task，调度器应该如何处理？

### 同优先级时间片

简单调度器通常假设一个优先级只有一个任务。

更完整的调度器需要：

```text
priority -> 该优先级下的 ready task 链表
```

同优先级任务可以轮流运行：

```text
T1 -> T2 -> T3 -> T1
```

这意味着不能只用：

```c
TcbTaskTable[priority]
```

而应该变成每个优先级对应一个任务链表。

### 延时链表优化

简单实现中，SysTick 每次可能扫描所有任务，检查谁该被唤醒。

更好的方案：

- 有序延时链表：最早唤醒的任务排在前面。
- 两个延时链表：一个处理正常 tick，一个处理 tick 溢出。
- 每次 tick 只处理已经到期的任务。

这样可以减少 SysTick 中断里的执行时间。

## 3. 任务和栈管理

### 栈溢出检测

创建任务栈时，在栈底放入固定标记值：

```text
0xA5A5A5A5 0xA5A5A5A5 ...
```

之后检查这些标记是否被覆盖。

可以检查的位置：

- 上下文切换时。
- 调试命令中。
- 删除任务前。

### 栈水位统计

创建任务栈时，把整个栈填充为固定模式。运行一段时间后，扫描还剩多少模式没有被覆盖。

这样可以知道：

```text
这个任务实际用了多少栈？
```

这比凭感觉给栈大小靠谱。

### 任务删除

实用 RTOS 需要支持任务删除。

要处理的问题：

- 从 ready/delay/block 链表中移除任务。
- 释放任务栈。
- 释放 TCB。
- 如果删除的是当前任务，如何切换出去。
- 是否让 idle task 延迟回收资源。

## 4. 临界区和中断安全

### 临界区嵌套

简单临界区通常保存和恢复中断屏蔽状态。

后续要检查嵌套是否正确：

```c
enter();
enter();
exit();
exit();
```

第一次 `exit` 不能过早打开中断。

### 调度器锁

有些操作只需要禁止任务切换，不一定要长时间关闭中断。

可以设计 API：

```c
void scheduler_suspend(void);
void scheduler_resume(void);
```

适合用于：

- heap 操作。
- 链表操作。
- 批量修改任务状态。

### ISR 安全 API

中断里调用的 API 需要特殊设计：

- 不能阻塞。
- 临界区要短。
- 可以在中断退出后触发一次上下文切换。

常见命名方式：

```c
semaphore_release_from_isr();
queue_send_from_isr();
```

## 5. IPC 和同步机制

### 信号量

后续实现信号量时，可以思考：

- 是二值信号量，还是计数信号量？
- 超时后如何返回？
- 多个任务阻塞时唤醒谁？
- 按最高优先级唤醒，还是 FIFO？

### 互斥锁

互斥锁不只是二值信号量。

它通常还需要：

- 记录 owner。
- 是否支持递归锁。
- 优先级继承。

### 优先级反转

典型问题：

```text
低优先级任务持有 mutex。
高优先级任务等待这个 mutex。
中优先级任务一直运行。
结果高优先级任务被中优先级任务间接阻塞。
```

解决思路：

```text
临时把低优先级任务提升到高优先级，直到它释放 mutex。
```

这就是优先级继承。

### 消息队列

消息队列需要考虑：

- 固定消息大小，还是可变消息大小。
- 使用环形缓冲区，还是链表节点。
- 发送时是否可以阻塞。
- 接收时是否可以阻塞。
- 是否支持 ISR 中发送。

## 6. 健壮性

### 断言

可以对不应该发生的状态加断言：

- TCB 为 `NULL`。
- 优先级非法。
- 栈指针未对齐。
- 释放了堆范围外的指针。
- 空闲链表损坏。

嵌入式调试阶段可以直接停在死循环：

```c
while (1) {
}
```

### 错误码

复杂起来后，不要只返回 `NULL` 或 `false`。

可以定义统一错误码：

```c
typedef enum {
    RTOS_OK,
    RTOS_ERR_NO_MEMORY,
    RTOS_ERR_INVALID_ARG,
    RTOS_ERR_TIMEOUT,
    RTOS_ERR_ISR_CONTEXT,
} rtos_status_t;
```

### 调试统计信息

有价值的统计项：

- 上下文切换次数。
- tick 次数。
- 当前剩余 heap。
- 历史最小剩余 heap。
- 内存分配失败次数。
- 每个任务最大栈使用量。
- 每个任务运行时间统计。

## 7. 可移植性

当前实现强依赖 Cortex-M。

后续可以隔离这些部分：

- 上下文切换汇编。
- SVC 启动第一个任务。
- PendSV 触发。
- 临界区实现。
- SysTick 配置。

可以逐步整理成：

```text
kernel/
  task.c
  heap.c
  list.c
  queue.c
portable/
  cortex_m3/
    port.c
    port_asm.s
```

这样 kernel 逻辑更清楚，也方便以后移植到别的平台。

## 8. 建议学习顺序

完成基础 RTOS 后，建议按这个顺序回来优化：

1. 加固当前 heap 分配器。
2. 添加 heap 统计信息和简单链表损坏检查。
3. 单独实现固定块 bitmap 分配器。
4. 实现多级内存池。
5. 增加栈溢出检测和栈水位统计。
6. 优化延时链表。
7. 支持同优先级多个任务。
8. 给信号量增加超时行为。
9. 实现 mutex 和优先级继承。
10. 分离 kernel 代码和 Cortex-M port 代码。

每一步都尽量小。一个小 RTOS 之所以适合学习，就是因为每个机制都能单独讲清楚。
